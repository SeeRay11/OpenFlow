## H. Risks
1. Dev host runs under node, prod under Bun: PTY, `Bun.spawn`, WS must be runtime-neutral or force `bun --bun`.
2. Host-tool/`--tools` interplay and `prompt`-approval-over-RPC are [INFERENCE]; probe with a throwaway `omp --mode rpc` before design freeze.
3. Single in-process serialization (`serialize()`, `chains`) protects only one host; two hosts same project still race (store.ts:1431).
4. Run state lives in the page (FLOW.md:174): resume relied on server-side sessions; with child-per-session owned by host, a host restart kills all sessions → need `--session-dir` + `--resume <id>`.
5. Orphan children: reuse process-group kill (opencode-process.ts:97-122) and SIGINT/SIGTERM teardown on both hosts; vite `httpServer.close` hook.
6. Secret hygiene: SUBSTRATE_TOKEN/OPENROUTER_API_KEY must be env-passed to children, never into argv, overlay files, SSE frames or logs; `/flow/api/env` stays names-only.
7. Models/credentials UI (providers-panel, spend/usage from `usage.ts`, `isFreeModel`) depend on opencode catalog shapes — largest src rewrite.
8. Existing global `~/.config/opencode/opencode.json` MCP/agent entries are still ingested by omp (mcp-config.md "OpenCode" import) → stale `mcp.openflow` entry would register a duplicate `mcp__openflow_*` beside host tools; installer cleanup/`uninstall` once at migration.
9. Tests deleted/rewritten: launch.test, opencode-process.test, store.test (routes), engine.test (client fakes), validate.test (permissionBlock).
