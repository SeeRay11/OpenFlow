# Phase 7: Parity checklist (MIG-03)

**Milestone:** v1.4.0 "Omp Engine" · **Branch:** `omp-engine` · **Package:** `packages/flow`
**Compared:** the OpenCode build at `3e1088ace` (the commit before the engine work) against `7f54a3453` (HEAD at the re-check; first written against `a73f2c165`).
**Written:** 2026-10-19, from the code, the tests (listed by name, the full suite was not run for this document) and the live observations recorded for this milestone. Where a row rests on a reading of the code or of omp's docs rather than on a test or an observation, it says so.

## How to read this

- **Status** is one of: `parity` (same behaviour), `replaced` (works differently, on purpose, user outcome kept), `dropped` (removed, reason given), `gap` (not met).
- **Evidence** names test files and, separately, live checks. "Live" means observed against real omp 18.12.2 and the real Agent Substrate on 2026-10-19. A live check that is not in the milestone's recorded list is not claimed.
- Old behaviour is cited from the phase-1 discovery reports (`.planning/phases/01-discovery-engine-port/discovery/01-engine-contract.md`, `02-host-store.md`, `03-ui-coupling.md`) and from `git show 3e1088ace:<path>`. New behaviour is cited at HEAD. Paths are relative to `packages/flow`.
- Three gate reports (QA, Review, Security) were run against earlier commits. Most findings were fixed in the commits after them (`9ffeda884` … `7f54a3453`); this file states what is true at HEAD and names the findings that are still open.
- A few rows describe things the old build never had (Uplift, Substrate memory, Swarm, the terminal) because MIG-03 and the roadmap name them as acceptance criteria. They are marked "(new)" in the old-behaviour column. A `gap` on a "(new)" row is a missed requirement, not a regression.

At HEAD (`7f54a3453`) no row is `gap`. Three items were open when this was first written and are now closed: **G-1** per-card MCP checkboxes (removed), **G-2** swarm step retry (requirement amended: Agent Swarm owns the retry ladder), **G-3** `FakeEngine` and contract suite (added). Detail in "Known gaps and residual risks".

## Dropped on purpose

- **Provider key panel and key import.** `ProvidersPanel`, `GET/POST cli-keys`, `lib/cli-auth.ts`. omp holds provider logins. A login is made with `/login` in the terminal or copied with **Copy logins**; the app stores none and no key crosses OpenFlow HTTP.
- **Restart-engine button and dialog.** `ui/engine-dialog.tsx`, `POST server/restart`, `FLOW_MANAGE_SERVER`. There is no long-lived engine to restart; each card is a fresh process that reads the current settings. Changes apply to the next card session.
- **Zen free models.** `lib/zen.ts`, `GET zen-models`, `isFreeModel`, `suggestedFreeDefault`. They belonged to the removed engine's bundled provider. A model id from that provider is flagged by migration and the card does not run until a model is picked.
- **Repackage.** `lib/repackage.ts` rewrote `provider.<id>.npm` in the global opencode config. omp owns provider setup.
- **Dispatch MCP server.** `mcp/dispatch.ts`, `lib/dispatch-tool.ts`. Replaced by omp RPC host tools of the same names and schemas; `MCP_REACHES_SESSIONS` is now true.
- **`opencode serve` supervisor and ports.** `lib/opencode-process.ts`, port 4096, `/api/health`, `OPENCODE_SERVER_URL`, `OPENCODE_SERVE_COMMAND`, the `-s` and `-m` launcher flags, and the `/api /global /event /mcp` proxies in both hosts.
- **Per-card MCP allowlist enforcement.** What is true: omp has no per-session MCP selection and no setting in the `--config` overlay that switches an MCP server off. Every card sees every server the `openflow` profile has configured, plus any server omp discovers from the project (`.mcp.json`) or from imported tool configs. Server allow and deny lives in the profile's `mcp.json` (`enabled: false` or `disabledServers`), which affects every card at once. The per-card control and `CardSpec.mcp` were removed in `bf22d48a9`; the inspector states the limit; an old `agent.mcp` is dropped silently on load.
- **`x-opencode-directory`.** The per-request directory header is replaced by `--cwd` on the child, fixed at spawn.
- **Also dropped:** MCP live status and connect/disconnect (`mcpStatus`, `mcpConnect`, `mcpDisconnect`); the unknown-agent preflight and the stale-engine restart path; the inspector's agent select and opencode agent names; generated `.opencode.json` agent files and the global-config merge with its `.bak` files.

## Intentional differences users will notice

- **Install and first run.** omp 18.12.2 or newer must be installed. The `openflow` profile starts with no logins and the model menu is empty until **Copy logins** or `/login`.
- **Everything is configured in one place.** Titlebar: one **Omp settings** button replaces the keys, restart and merge-agents buttons. Settings are saved to `<state>/omp-settings.json` and apply to the next card, not a running one.
- **Auto permission means omp's `yolo` mode.** Nothing asks; the card's tool toggles are the only limit. Ask-me mode uses omp's own approval prompts, with omp's options (`always` is "for this session" and only where omp offers it).
- **Prompts are rewritten before they run.** Prompt Uplift is on by default for every card's own task. A card can wait up to the planner limit (240 s by default) and, if the planner fails, stops and asks. `raw:` or the settings toggle turns it off.
- **Cards share memory.** A card reads project memory before it runs and writes its outcome afterwards, if Substrate is reachable; otherwise it runs without and says so. A card never receives a Substrate token. Forget retracts but Substrate keeps the entries until their ttl lapses.
- **Swarm is on by default (`auto`)** where its preflight passes, and loads agent-swarm's extension into the card; a failed preflight degrades the card to off with a reason.
- **MCP servers and skills moved** from the project's `opencode.json` and `.openflow/skills` to the `openflow` profile. Servers you had in the project config must be re-added there. A saved change applies to the next card session.
- **Cards run under isolated settings.** `--no-extensions`, an allowlisted environment (provider `*_API_KEY` yes; `SUBSTRATE_*`, `SWARM_*`, `*_TOKEN`, `*_SECRET` no), and role prompt, overlay and session files kept outside the repo.
- **Browser access is gated.** Another web page or a DNS-rebound name can no longer drive the API; curl and scripts without browser headers still work. A refusal is a 403 with a `forbidden-*` code.
- **A cap of 32 live omp sessions** and a 60 s startup deadline; a wide fan-out can see a 429 `too-many-sessions`.
- **Terminal dock** (`Ctrl+``): omp or the user's shell in the project; four sessions at most; off under `FLOW_ALLOW_REMOTE=1`.
- **Old pipelines and run logs open with a notice** ("from an earlier build"), and cards with old model ids do not run until a model is picked. Old sessions cannot be resumed.
- **Models and cost** come from omp's catalog. Reasoning tokens read as 0.
- **Swarm retries are Agent Swarm's, not OpenFlow's.** OpenFlow does not retry a failed swarm lane. Agent Swarm retries inside its own bounded ladder (`max_attempts`, then `ESCALATED`), and the card shows the lane state omp reports and a final status when the card ends. There is deliberately no second retry layer. SWM-03 was amended accordingly.
- **There is no per-card MCP selection.** Every card sees every MCP server in the profile and any project `.mcp.json`. The inspector says so; the old per-card checkboxes are gone and an old `agent.mcp` is dropped silently on load.
- **Old run state is deleted.** Run directories under `<state>/omp/` untouched for 30 days are removed when the host starts; an old run's omp session can then no longer be resumed (the engine starts the card fresh).
- **Session titles read "Role · task"** in the Sessions panel, not the shared briefing's first line.
- **A hedged card output** that Substrate refuses as a fact is stored as a todo instead of being lost.

## Known gaps and residual risks

### Not met (the `gap` rows)

None. G-1 and G-3 are fixed in code and G-2 is a requirement amendment; see the three bullets below, which are kept so the history is visible.

- **G-1, per-card MCP checkboxes: fixed (`bf22d48a9`).** The checkboxes, `CardSpec.mcp` and the `agent.mcp` plumbing are gone; `ui/inspector.tsx:131-144` shows one line ("every card sees every MCP server configured in the Omp profile, plus any .mcp.json in the project") and a manage button; `migratePipeline` still recognises `mcp`, drops it silently and does not stamp the document (`migrate.test.ts` "an old per-card mcp allowlist loads with no note, is dropped, and does not stamp the document"); `card-spec.test.ts` asserts `cardSpec` has no `mcp`. `describeLaunch` no longer mentions MCP; it still has no caller outside its test and is dead code for the remaining tool-toggle notes.
- **G-2, failed swarm steps retry (SWM-03): amended, row is `replaced`.** Agent Swarm retries failed lanes itself inside a bounded ladder: a transient failure backs off per `swarm/retry.py` (capped exponential), FAILED goes to RETRY behind a fresh claim up to `max_attempts`, then ESCALATED (`agent-swarm/AGENTS.md:35,53,57`, `docs/substrate-leases.md:139`). OpenFlow adds no second retry layer, on purpose: a second layer would multiply cost and loops. OpenFlow's part is surfacing the final state (`flow.swarm.status`, the chip, a final settled status when the session ends or Stop is pressed: `session.test.ts` "disposing the session ends its swarm once…", `tracker.test.ts`). Limits of the evidence are under State and lifecycle.
- **G-3, no FakeEngine or contract suite (ENG-02): fixed (`46b7084e4`).** `src/server/testing/fake-engine.ts` and `src/server/engine-contract.ts` (39 `test(` scenarios by grep; the commit says 40) run against the fake (`src/server/engine-contract.test.ts`) and against the real browser client over HTTP to a real `createHost` on the stub omp (`lib/host/engine-contract.test.ts`). I read these files; I did not run them.

### Platform paths never run in practice

- **Windows and macOS PTY and process-group paths are unverified.** Everything observed live was on Linux. On Windows the omp child is torn down with `taskkill /pid <pid> /T /F` (`lib/omp/rpc.ts`) and the PTY uses `@lydell/node-pty` with `useConptyDll` (`lib/terminal/pty-node.ts`); on macOS the POSIX group path is the same code as Linux but the prebuilt `spawn-helper` mode, ConPTY and the Bun PTY on those systems have not been exercised. The POSIX-only suites are skipped on Windows, so the Windows CI leg has not been shown to be green and the suites that would prove those paths do not run there.
- **The first-run omp setup wizard** in a brand-new isolated profile appears in the terminal's `omp` tab (observed live) and is skipped with `Ctrl+C`; README says so (`README.md:295`). RPC cards do not run it. It is a rough edge, not a blocker. The Copy logins path was observed with 12 logins into a throwaway isolated profile.
- **omp binary versions other than 18.12.2** are untested; the argv flags are checked against `omp --help` only when omp is installed (the CI runner has none, so CI never checks them).

### Secrets and permissions

- **The swarm signing key reaches swarm cards by value.** `SWARM_ED25519_KEY` and `SWARM_SIGNING_KEY` are copied from the host environment into the environment of a card whose swarm is on (`lib/omp/launch.ts:43-44,130-134`); the card's shell tool can read it. `SWARM_ED25519_KEY_FILE` passes only a path. The key is not in argv or a file, but the card is model-driven. (Security gate P2-1, open by design; the CHANGELOG states it.)
- **Provider `*_API_KEY` values reach every card** by design (omp resolves providers from the environment) and are readable by the card's shell.
- **`mcp.json` values are plain text** and include MCP `env` and `headers`.
- **State directories are 0755 and `state.json` is 0644** (`session.ts`, `rpc.ts` create directories with default modes; role prompt, overlay and meta files are 0600). omp's own session files were not inspected.
- **The planner receives broad secrets** (`ANTHROPIC_*`, `CLAUDE_CODE_*`, `SUBSTRATE_TOKEN`) and runs a program at a user-chosen path. That path can only be changed through the settings route, which the gate protects.
- **The version probe inherits the whole host environment** (`lib/omp/binary.ts`, Security P3), and `GET /env?names=` and `GET /browse` answer to any gated caller.
- **The gate does not authenticate.** It stops browsers acting for another site. Any local process, and any user on the same machine who can reach the port, still has the full API (as before). Requests without browser headers skip the Origin and fetch-metadata rules by design, and a custom request header is not required, so the gate relies on the browser sending `Origin` on cross-site POSTs. Bodiless same-site `GET`s from very old browsers that send neither header are not refused.
- **The Substrate token travels only to https, loopback, or the origin `SUBSTRATE_URL` names** (fixed in `a73f2c165`); a user-set URL on those terms still receives it.
- **`ghostty-web`** is pinned to a commit of a fork (`anomalyco/ghostty-web`) whose `package.json` points at `coder/ghostty-web` and ships a prebuilt wasm; provenance is unconfirmed (Security gate).

### State and lifecycle

- **Terminal host allows four PTYs while the UI uses one.** `PTY_LIMITS.maxSessions` is 4 (`shared/terminal.ts:59`, pinned by `terminal/host.test.ts`); the dock opens one at a time. TRM-01's "single global session" holds for the UI, not for a direct caller of the host's routes (which the gate and ticket still fence).
- **Substrate has no delete.** Forget writes retraction facts and a local ignore list (`<state>/memory-ignore.json`); the entries stay until their ttl. A different host or a lost ignore file reads them again. A re-dispatched sub-agent writes under a per-dispatch key. A hedged card output Substrate quarantines as a fact (`quarantine.speculative`) is re-sent once as a `todo` (`lib/substrate/memory.ts`); other quarantine reasons are not retried, and a todo that is also refused reports the original result. The 409 behaviour of Substrate was not exercised.
- **A stale `mcp.openflow` entry** written by the old dispatch-tool installer into the user's global opencode config points at the deleted `mcp/dispatch.ts`. omp imports `~/.config/opencode/opencode.json`, so a card may see a second, broken `openflow` server beside the host tools. Nothing cleans it and nothing was run to see the effect [INFERENCE from omp://mcp-config.md].
- **Cards see more MCP servers than the profile lists.** Besides the `openflow` profile's `mcp.json`, omp discovers a project's `.omp/mcp.json`, `.mcp.json` and imported tool configs (omp://mcp-config.md). The inspector now says "any .mcp.json in the project"; the omp docs were read, not run.
- **Swarm retry is Agent Swarm's, and the card only sees lane states.** The tracker reads omp's `task` sub-agent frames (`lib/swarm/tracker.ts`: queued, running, completed, failed, cancelled). It does not read Agent Swarm's task-store states, so `RETRY` and `ESCALATED` are not shown as such: a lane Swarm retries or escalates appears as whatever omp reported for it. No retry or escalation was observed live, and I did not confirm that the retry ladder in `swarm/retry.py` runs on the omp-extension path the cards use rather than only under `swarm_run.py`.
- **Run state is pruned only at host start.** `lib/omp/prune.ts` removes run directories under `<state>/omp/<project-hash>/` whose newest file is older than 30 days, once, 15 s after the host starts, for the project that is current when that timer fires; a run still held by a session is kept. The `uplift/` directory, loose files and symlinks are never touched, so uplift results still accumulate, and other projects' state roots are pruned only when the host runs with that project. A long-running host never prunes again until restarted.
- **A hard kill of the host** (SIGKILL, crash) skips the exit safety net; omp children are in their own process groups and should exit on stdin EOF, but a tool subprocess may survive [INFERENCE, not tested].
- **A withdrawn approval dialog is not withdrawn in the browser**; a late click gives "permission reply failed".
- **A fan-out above 32 sessions** returns 429 `too-many-sessions`. The engine's rate-limit classifier probably matches that text and retries with backoff [INFERENCE]; not tested.
- **Message store trim** (300 messages) can under-report usage of a very long card.
